# Видение: LLM-сервис для Беларуси

Конспект продуктовой идеи: сервис на базе LLM, ориентированный на пользователей из Беларуси, с возможностью интеграции с локальными сервисами. Сюда же влит старый черновик MVP — он был про то же самое, но врозь.

!!! note "Статус"
    Это **бэклог**, а не спецификация: замысел, из которого черпают идеи, а не список работ. Как читать этот раздел — на [странице бэклога](index.md).

    Реализация живёт в других местах: витрина для людей — [первая версия](../v1/index.md) и планы [второй](../v2/index.md), корпоративный контур (OAuth/SSO, роли, агенты) — [отдельный деплой LibreChat](../v2/librechat.md). Две двери не путаются — см. [аудитории](../audiences.md), [дорожная карта](../roadmap.md), [о сервисе](../about.md).

    Технически старт уже есть: код витрины держит чат, токены и OpenAI-совместимый прокси (Python 3.13+, Node.js 24+). Доменный продукт поверх него ещё предстоит выбрать и сузить.

## Почему это может сработать

### Язык

- В деловой среде и интернете доминирует русский; белорусский имеет государственный статус и культурную значимость.
- Поддержка **обоих языков** (с переключением) полезна для повседневного общения и официальных документов.
- Примеры: помощь с формами налоговой, объяснение законодательства простым языком, перевод беларуский ↔ русский.

### Госуслуги и бюрократия

Многие пользователи путаются в порталах вроде [egov.by](https://www.egov.by), банковских и коммунальных системах. LLM-ассистент может:

- подсказывать, какой документ нужен для услуги;
- объяснять термины простыми словами;
- помогать заполнять формы (подсказки, голосовой ввод);
- при наличии API — проверять статус заявки.

### Локальная коммерция и быт

Возможные направления интеграций:

- банки (Belarusbank, Priorbank, Белинвестбанк — где есть API или чат-боты);
- телеком (A1, МТС, life:): тарифы, подключение услуг;
- доставка еды/товаров (локальные сервисы; в MVP чата — неофициальная интеграция с [pzz.by](https://pzz.by));
- транспорт (расписание, билеты);
- маркетплейсы / объявления (например, Kufar).

### Цифровое неравенство

Простой текстовый/голосовой интерфейс полезен пожилым людям, жителям регионов и тем, кто менее уверен в цифровых навыках.

## Ключевые вызовы

### Юридические и санкционные ограничения

- Санкции ЕС/США могут влиять на доступ к облачным LLM и части провайдеров.
- Меры: проверять политики провайдеров; при необходимости — self-host открытых моделей; консультация с IT-юристом; соблюдение Закона РБ «О персональных данных».

### Техническая интеграция

Многие локальные сервисы (госорганы, старые банковские системы) имеют устаревшие или закрытые API.

Практичный подход:

1. Начать с сервисов, у которых уже есть нормальный API.
2. Для закрытых систем — осторожно: RPA / парсинг только при правовой допустимости.
3. Партнёрства: ассистент снижает нагрузку на поддержку — это аргумент для банков/госа.

### Доверие и конкуренция

- Ясно описывать обработку данных.
- Показывать источники («на основе egov.by на [дата]»).
- Для критичных советов (налоги и т.п.) — ссылки на официальные первоисточники.
- MVP вокруг **одной** высокоценной ниши, а не «универсального бота».

### Языковая и культурная адаптация

Нужны не только переводы UI, но и белорусские реалии: названия документов, аббревиатуры, локальный русский. При fine-tuning — локальные датасеты (законы, формы, типичные запросы).

## Сценарии использования

| Сценарий | Как помогает LLM | Интеграция |
|----------|------------------|------------|
| **egov.by** | Какие документы, как оформить пособие, статус заявки | API портала / отдельные сервисы |
| **Банки** | Термины в выписке, условия кредита, черновик обращения | API банка или загрузка файла с согласия |
| **ЖКХ** | Показания счётчиков, начисления, субсидии | ЕРЦ / поставщики |
| **Здоровье** | Поликлиника, запись к врачу, термины | Открытые базы учреждений |
| **События** | Мероприятия, волонтёрство, изменения локальных правил | Афиши / местные источники |

## Краткая оценка

| Что работает | Барьеры | Путь к MVP |
|--------------|---------|------------|
| Высокий спрос на упрощение госуслуг, банков, ЖКХ | Санкции, доступ к облачным LLM, ОПД | Один конкретный сервис (напр. соцвыплаты через egov) |
| Двуязычность RU/BE | Слабые/закрытые API локальных систем | Цель: N реальных запросов за месяц; квази-интеграции осознанно |
| Интерес к ИИ-стартапам, возможные гранты/ПВТ | Доверие и конкуренция «общих» чат-ботов | Прозрачность, минимум хранения, ссылки на источники |
| B2B API / партнёрства позже | Стоимость GPU / self-host при масштабе | Сначала прокси (как сейчас в aichat), self-host — по необходимости |

## Первый шаг

1. **Один кейс.** Выбрать одну решаемую боль (например: «как оформить пособие по уходу за ребёнком»), не весь egov сразу.
2. **Юридическая проверка.** Санкции и доступ к провайдерам LLM из РБ; требования ОПД к хранению запросов и ПДн.
3. **Выбор LLM-слоя.** Сейчас — OpenRouter free через `aichat`. Альтернатива при ограничениях: self-host (Llama / Mistral) на VPS в допустимой юрисдикции.
4. **Пользовательский путь.** Первый вопрос → язык/контекст → ответ со ссылками → (позже) статус заявки через интеграцию.

| Шаг | Что сделать | Ожидание |
|-----|-------------|----------|
| 1 | Веб-чат (уже есть в aichat) + системный промпт под кейс | Узкий ассистент без «универсальности» |
| 2 | База знаний / ссылки на официальные страницы по кейсу | Ответы с источниками, меньше галлюцинаций |
| 3 | Одна интеграция (если API есть) или честный «ручной» статус | Реальная польза, не только болтовня |
| 4 | Канал доставки (сайт и/или Telegram) | Обратная связь от первых пользователей |
| 5 | RU + BE в ответах/UI | Локализация без раздувания scope |

!!! tip "Бюджет"
    Точные цифры зависят от хостинга LLM и объёма трафика.
    Пока достаточно текущего shared hosting + OpenRouter free; GPU self-host — отдельное решение после проверки спроса.

## Открытые вопросы

1. На каком **одном** виде сервисов сфокусировать первый релиз?
2. Есть ли опыт/доступ к API госуслуг или банков?
