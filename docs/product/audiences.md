# Две аудитории, два контура

Зафиксированное решение: **этот репозиторий (`aichat`) не заменяем на LibreChat.** Нужны оба контура, у каждого своя дверь.

## Обычные люди — витрина `aichat`

Публичный чат в браузере: войти, спросить, получить ответ, при необходимости погоду, картинку, заказ пиццы. Без выбора моделей на каждом шагу, без конструктора агентов, без корпоративного ACL.

Сюда не тащим SSO предприятия, загрузку чужих дисков «на всякий случай» и зоопарк MCP. Сложность прячем. Человек не программист и не админ конторы.

Код и деплой — этот репозиторий.

## Компании — отдельный LibreChat

Для организаций поднимаем **другой** инстанс: LibreChat. Там уместны OAuth/SSO, роли, контроль доступа, агенты, MCP, то, без чего ИБ и закупки не пустят модель в контур фирмы.

Это не форк `aichat` и не переезд текущих пользователей. Бытовые инструменты (погода, pzz) при желании позже подключают к LibreChat снаружи (MCP или OpenAPI), не вырезая их из витрины.

Обычных людей на LibreChat по умолчанию не переводим: им достаточно витрины. LibreChat — дверь для конторы.

## Что из этого следует

| | Витрина `aichat` | LibreChat |
|---|---|---|
| Кто | Человек «с улицы» | Сотрудник / арендатор конторы |
| Обещание | Простой чат и местный быт | Контролируемый доступ к моделям и агентам |
| Вход | Как сейчас (почта, Google/Apple) | Корпоративный OAuth/SSO и роли |
| Этот репозиторий | Да, основной продукт | Нет; отдельный деплой апстрима |

Развитие витрины — стабильность, вёрстка, уже существующие руки. LibreChat — отдельный объём (хостинг, обновления, политика доступа), его не смешиваем с MVP публичного чата.
