# Ручной тест через Playwright перед деплоем

Сценарий прогоняет деплой сайта (mzg.by) и смежный UX в браузере Chromium
под управлением `playwright-cli`. Дата: 1 октября 2026. Сборка — ветка
`pr-bundle` (после влития трёх Cursor-PR и мастера).

## Стенд

| Параметр | Значение |
|----------|----------|
| Приложение | `http://localhost:20000/` (Makefile-порт `PORT=20000`) |
| Окружение | `OPENROUTER_API_KEY` задан; `MZG_SITES_FOLDER=/tmp/mzg` |
| Браузер | `playwright-cli open --browser=chromium` |
| Аккаунт | `qa+<unix_ts>@example.test` / `QaPass12345` (создан при прогоне) |

## Наблюдения (не блокирующие)

- **404 favicon.ico** — единственная ошибка в консоли. Иконки PWA есть
  (`manifest.webmanifest` отдаёт их по ссылкам), но `/favicon.ico` отдать нечем:
  положить копию в `frontend/dist` или шаблон лендинга.
- **Тестовый домен отдал 404** — ожидаемо: `mzg.by`-роутинг настраивается на
  целевом хостинге, локальный деплой складывает только файл в папку.
  Проверка публикации — по факту файла, не по HTTP-ответу домена.
- Прогресс рук (PR26) виден в блоке «Рассуждение» — раскрывается стрелкой,
  текст хода («Узнаю погоду…» на шаге 3) внутри.
- После прогона добавлен `frontend/public/favicon.ico` (ICO-контейнер c PNG из
  `scripts/generate_pwa_icons.py`) и роут `GET /favicon.ico`
  (`app/routes/pages.py`) — единственный 404 в консоли закрыт.

## Как повторить

```bash
make run                          # порт 20000 по умолчанию
playwright-cli open http://localhost:20000/ --browser=chromium
playwright-cli click "getByRole('link', { name: 'Создать аккаунт' })"
# …дальше по таблице: snapshot → fill/click по refs
playwright-cli close
```

Логи запросов и снимки страниц playwright-cli складывает в `.playwright-cli/`
(в git не попадают).
